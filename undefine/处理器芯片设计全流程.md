```Plain Text
字节序：
通常来说，ISA层次定义的存储器是按字节寻址的，每个内存地址对应1个字节，但是对于多字节的数据，如何在存储器中存放，就成了一个需要考虑的问题。

1. 小端(little-endian)-低地址存放低位字节，高地址存放高位字节；
2. 大端(big-endian)-低地址存放高位字节，高地址存放低位字节；
   
小端的优势：
	1. 按不同长度的数据类型解释同一个数据时，无需移动字节；
	      x                          x      x+1    x+2   x+3                     
	   +------+  little-endian   +------+------+------+------+
	   | 0x12 | ---------------> | 0x12 | 0x00 | 0x00 | 0x00 |
	   +------+     big-endian   +------+------+------+------+
	   | 0x12 | ---------------> | 0x00 | 0x00 | 0x00 | 0x12 |
	   +------+                  +------+------+------+------+ 
	2. 算术运算的进位方向与地址方向一致，可以从低地址开始计算；
	   读到低位字节就可以开始计算了，不用一直读到高位才能计算，对于带宽较低的计算机，性能更高，
	   所以CPU通常采用小段存储。
	3. 高精度大整数库也采用小端存储；

大端的优势：
	1. 符合人类的阅读规则，0x12345678 -> 0x12 0x34 0x56 0x78(从左到有地址增加)；
	2. 网络传输通常使用大端；
	3. 可以快速判断一个数的符号；
	   
RISC-V中的字节序：
	1. 数据的存储：RISC-V没有定死，可以根据不同场景来选择；
	2. 指令的存储：RISC-V规定以16位的包为单位的小端存储；
```

# H3. 逻辑设计

```Plain Text
关于Verilog的思考：

1. Verilog是RTL设计语言？ 不，Verilog的本质是一门"事件建模语言"，"Originally, Verilog was only intended to describe and allow simulation"，用Verilog来设计可综合电路是后来的事情，Verilog中只划出一部分子集，赋予它们可综合的含义；
   
2. Verilog包含三种建模方式：(1)结构化建模。实例化，端口连线；(2)数据流建模。assign-连线，运算符-功能部件，*/%...一般不用，它会综合处一个周期内很复杂的电路，面积、功耗、延迟都很大；(3)行为建模。用来描述时序逻辑元件。
```

**问题1-RTL设计过程不直观**
	行为建模的设计过程：
		1. RTL设计者看着电路图的结构
		2. 心里想象电路的行为
		3. 用事件模型的方式重新思考电路行为
		4. 再用行为建模的方式来描述事件模型
		5. 综合器根据行为建模的描述推导出相应的电路
	从第2步就已经偏离初衷了，都已经有电路图的结构了，直接描述电路结构不就行了嘛😂。绕这么大一圈，白白增加出错的风险。


**问题2-让初学者忽略电路设计的本质**
	部分初学者会**跳过第1步**，直接从第2步开始，这个是一个更可怕的问题。**拍脑袋想一个行为**，仿真过了就交给综合器来生成电路，有点HLS高层次综合的味道了，然而大多时候只会得到**PPA质量很低的电路**。



**问题3-把老师绕晕，让学生从课堂开始误入歧途**
	你可能很容易在课本等学习资料中找到类似的描述：
	> 在Verilog中，各语句是并发执行的，模块中所有的assign语句、always语句块和实例化语句，其执行顺序不分先后。而if语句是顺序执行的语句，其执行过程中必须先判断if后的条件，如果满足条件则执行if后的语句，否则执行else后的语句。Verilog语法规定，顺序执行的语句必须包含中always块中，always块中的语句按照它们在代码中出现的顺序执行。
	**灵魂拷问：**
		1. 在RTL设计中，什么叫**执行**？
		2. 是谁在执行Verilog的语句？是电路，综合器，还是其他的？
		3. `if的条件满足，就不执行else后的语句`，这里的`不执行`又是什么意思？和电路有什么联系？
		4. 有`并发执行`，又有`顺序执行`，还有`任何一个变量发生变化就立即执行`，以及`在任何情况下都执行`，它们都是如何在电路中体现的？



**建议！：远离行为建模，回归RTL设计的本质**
	RTL设计=直接描述电路结构=实例化+连线
		1. 想象有一个空白的电路板，还有一张设计图纸
		2. 实例化=按照图纸拿一个元件(门电路，触发器...)放在电路板上
		3. 连线=按照图纸用导线将这些元件的引脚连起来
	用数据流建模和结构化建模就可以实现上述本质：
		+ 为了支持触发器/存储器，可以写一个参数化的module。内部用`always`实现(简单可控)，但通过结构化建模屏蔽实现细节；
		+ 少用或不用行为建模。有的企业限制`always`中的编码风格，有的企业甚至不允许写`always`，例如蜂鸟E203处理器代码没有任何`always`语句，如果你用Chisel，不建议使用`when`和`switch`；



**存储器的实现：**
	真实的存储器复杂，将来接入SoC时使用可以流片的真实存储器。因此目前实现一个简单的存储器即可，反正最后都是要换的。甚至没有必要使用RTL实现，可以通过DPI-C机制，让Verilog代码访问用C代码实现的仿真环境。

```Verilog
import "DPI-C" function int pmem_read(input int raddr);
import "DPI-C" function void pmem_write(
	input int waddr, input int wdata, input byte wmask);
always @(*) begin
	rdata = (valid ? pmem_read(raddr):0);
	if (wen && valid) pmem_write(waddr, wdata, wmask);
```

```C
extern "C" int pmem_read(int raddr) {
	// 总是读取地址为 raddr & ~0x3u 的 4 字节返回
}
extern "C" void pmem_write(int waddr, int wdata, char wmask){
	// 总是往地址为 waddr & ～0x3u 的 4 字节按写掩码 wmask 写入 wdata
	// wmask 中每比特表示 wdata 中 1 个字节的掩码
	// 如 wmask = 0x3 代表了只写入最低 2 个字节，内存中的其他字节保持不变
}
```

这两个内存读写函数模拟了**32位总线**的行为
+ 只支持地址按4字节对齐的读写；
+ 其中读操作总是返回按4字节对齐读出的数据，由RTL代码根据读地址选择出需要的部分；

完成逻辑设计之后，就是要**在处理器上运行程序**。
	1. 如何将程序编译成ISA的指令序列？
	2. 如何将编译出来的指令序列放置在存储器中？
	3. 如何向程序提供`printf()`库函数的功能？
	4. 如何向程序提供动态内存管理的功能？`printf()`可能需要调用`malloc()`
	5. 从`main()`函数返回后，如何指示程序结束？

一生一芯中针对NPC处理器体提供了一个用于构建程序的项目`abstact-machine`(简称AM)，AM=裸机运行时环境，为程序直接运行在NPC上提供必要的支持。

AM如何完成对软件的支持，从而解决了上述问题：
1. 如何将程序编译成ISA的指令序列？ISA这里指minirv
	1. 先通过`riscv64-linux-gnu-gcc`将C代码编译成RISC-V汇编代码
	2. 然后利用汇编层次的宏定义，将其他指令展开成8条minirv指令
	3. 最后将宏展开后的汇编代码转换成二进制的指令序列
2. 如何将编译出的指令序列放置在存储器中？
	1. 在仿真环境中通过文件操作，将编译出的指令序列读入存储器中
3. 如何向程序提供`printf()`库函数的功能？
	1. 提供`klib`库函数的实现，以及`putch()`用于输出一个字符
4. 如何向程序提供动态内存管理的功能？
	1. 提供堆区的范围和`malloc()`的实现
5. 从`main()`函数返回后，如何指示程序结束？
	1. 在`halt()`中执行`ebreak`指令，通知仿真环境结束仿真



# H5. 程序和输入输出

一种不主流的方法是采用**端口映射I/O**：在ISA中增加IO指令，通过指令的`idx`设备编号来指示一个设备。

在RISC-V中，输入输出是通过**内存映射I/O**(Memory-mapped I/O)方式来进行的。指定设备的方式是根据**访存地址的范围**来决定是访问存储器，还是其他设备。


为了让程序可以使用串口进行输出，还需要在处理器中添加一个串口，不过就目前来说，只需要在仿真环境中添加一个串口的简单行为模型就行：
```C
extern "C" void pmem_write(int waddr, int wdata, char wmask){
	if(waddr == 0x1000_0000){ // 写入 UART
		fputs(wdata & 0xff, stderr); // 在stdio.h中定义
		return;
	}
	// 写入存储器数组
}
```
上述行为模型通过`if`语句实现内存映射I/O的功能，在进行存储器写操作时，如果目标地址是`0x1000_0000`，就写入串口，通过`fputc()`输出`wdata`低8位所表示的字节，模仿UART输出的行为。
接入SoC时，再引入真实的串口控制器。

有了串口，就可以在处理器上运行各种需要输出信息的程序了，各种benchmark(只看对错，不评分），甚至是AI大模型(无交互）。

为了能个给各个benchmark打分，我们需要计时功能，这就需要时钟模块：
```C
unsigned long long get_time(){
	// 返回从仿真开始所经过的时间，单位为微妙
	// 可通过gettimeofday()来实现，gettimeofday()来获取当前的系统时间
	return 0;
}

extern "C" int pmem_read(int raddr){
	// ...
	// 读出时钟的低32位
	else if(raddr == 0x2000_0000){
		return get_time() & 0xffffffff; 
	} // 读出时钟的高32位
	else if(raddr -- 0x2000_0004){
		return get_time() >> 32; 
	} // 读出存储器的数组
}
```
在AM中实现读取时钟的函数，在函数中访问时钟的行为模型，就可以让处理器上的程序具备计时功能。


# H6. 功能验证

1. 测试(testing)：查看系统在特定输入(即测试用例)的情况下，行为是否符合预期；
	1. 单元测试——与具体模块相关
	2. 集成测试——AM上的各种小规模程序
	3. 系统测试——RT-Thread，红白机游戏...

**通过测试无法说明系统没有bug**，需要通过全覆盖的测试(枚举)才能说明，但开销通常无法承受。

2. 证明(proving)：形式化验证，证明一个命题是否存在所有情况下都成立；
	1. 覆盖所有可能性，最终要么证明成立，要么给出反例
	2. 无需测试用例
	3. 需要把`什么是正确`用命题表达出来


在测试过程中，如何高效地定位错误？
DiffTest，差分测试，一个程序在RTL实现的处理器上运行，和在C语言实现的指令集模拟器中运行，行为应当一致。
```C
while(???) { // 以下为伪代码
	dut_single_cycle(); // design_under_test
	ref_inst_cycle(); // 参考模型
	uint8_t *dut_regs = &top->rootp->CPU_DOT_gpr_ext_DOT_Memory;
	uint8_t *ref_regs = ref_get_regs();
	int is_diff = check_regs(dut_regs, ref_regs);
	if (is_diff) {
		printf("GPR different\n");
		printf("Simulation stop\n");
		break;
	}
}
```
核心基本思想：对比每条指令执行后，处理器和模拟器的寄存器状态是否一致，如果不一致，就马上报错，从而找到第一条行为不一致的指令。
